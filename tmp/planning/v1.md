# OmaPihole V1

Pi-hole presence in the Omarchy bar: always-visible state, one daily action (timed pause), and a glance that is actually glanceable.

This is the V1 spec. Implement against it; do not grow it in the same ship.

**Repo:** https://github.com/BVisagie/omarchy-omapihole (private)  
**Status:** planning only. No plugin code yet.

---

## 1. Product thesis

A “stunning stats panel that is not the dashboard” is how Homarr, Homepage, and Glance already solved Pi-hole in a browser. On a desktop bar, a prettier excerpt of the Pi-hole homepage is something you look at twice and then stop opening.

The strong version is **Pi-hole presence in the shell**:

1. Notice blocking is off (you paused it for a broken site and forgot).
2. Pause blocking for 30s / 5m / 15m without leaving the current window.
3. Check whether the network is noisy / what was just blocked.

If the plugin cannot do (1) and (2), it is wallpaper. Glance’s DNS widget is the honest comparison for *density* (big block %, 24h bars, short last-blocked list). It is still a startpage widget. On Omarchy, the bar pill is 90% of the product and the panel is the other 10%.

Weather, Omastonk, and Quadrant work because they live in the bar and earn the click. Homelab dashboards live in a browser tab. Do not compete with the tab.

| One-liner | Pi-hole presence in the Omarchy bar: state, pause, glance. |

Tagline for the README, not the bar: *Not a dashboard. A shield in the bar, a pause in the panel.*

Sits in the `oma*` family (Omastonk, OmaCast, OmaHUD). Reads as “Omarchy + Pi-hole.” Does not collide with the reserved `omarchy.*` namespace or with OpenAPI (`omapi`).

`bvisagie.omapihole` matches You’ve Got Mail (`bvisagie.you-got-mail`). Quadrant uses `dev.bvisagie.quadrant`; this plugin does not copy that prefix.

Rejected names:

- `omahole` — too cute for a control that opens a DNS hole
- `omapi` — OpenAPI collision
- `omarchy.pihole` / `omarchy.omapihole` — reserved first-party namespace

## 3. Job to be done

A person running Pi-hole on the LAN wants to know, without opening a browser:

1. Is blocking on.
2. Pause it for 30s / 5m / 15m because a site is broken.
3. Glance at today’s block rate and what was just blocked.

If a screen does not serve one of those three, it is out of V1.

## 4. Non-goals (V1)

Explicit refusals, not “later maybe” in the same PR:

- Pi-hole v5 (`/admin/api.php`)
- AdGuard Home, Technitium, Unbound
- Multiple instances / HA
- Query log, clients, groups, lists, DHCP
- Gravity update, list management
- TOTP / web-password 2FA login (app password only)
- Tabs, Pi-hole brand colors, a settings page beyond the empty-state form
- Notifications that blocking was left off (V1.1, needs a `service` kind)
- Password stored in `shell.json`

## 5. Surfaces

### 5.1 Bar

One `BarIconButton`. Shield glyph + one label. Color is state.

| State | Label | Color |
|---|---|---|
| Unconfigured | glyph only | muted |
| Enabled | `34%` (default) | normal / accent |
| Paused with timer | remaining `4:32` | urgent |
| Disabled, no timer | `off` | urgent |
| Offline / TLS / timeout | `—` | warning |
| Auth failed | `auth` | warning |

While blocking is off, the pause countdown **replaces** the metric. That is the ambient fact that matters. `barMetric` only applies when blocking is on.

Clicks:

| Input | Action |
|---|---|
| Left | Toggle panel |
| Middle | Refresh now |
| Right | Open dashboard URL in the default browser |

Tooltip (only when the panel is closed): host, queries today, blocked today, last blocked domain, or the error string. No tooltip while the panel is open — weather’s rule.

Summon contract, copied from weather: `opened`, `open()`, `close()`, `closeForPopoutSwitch()`, `popoutSwitchClosing` on the **bar-widget root**, because `Bar.findPanelWidget` looks at the slot item, not the nested panel.

Right-click opens the real UI rather than toggling blocking. Pause already lives on 1/2/3 and the chips. A misclick that disables network-wide blocking is a bad default.

### 5.2 Panel

One screen. No tabs. ~400px wide, theme tokens only (`Style`, `Color`). KeyboardPanel + PanelKeyCatcher.

```
┌──────────────────────────────────────────┐
│  ⬤ Blocking on              pi.hole   ↗  │  header: status dot, host, open-dashboard
│                                          │
│              34%                         │  hero: percent_blocked, 1 decimal
│           blocked today                  │
│     ▁▂▃▅▆▇█▆▄▃▂  24h total / blocked     │  dual sparkline, theme colors
│                                          │
│   48.2k queries     16.4k blocked        │  compact numbers, supporting weight
│   2.1k domains      187k gravity         │
│                                          │
│   [ 30s ]  [ 5m ]  [ 15m ]  [ Enable ]   │  pause chips; Enable is resume
│                                          │
│   last blocked                           │
│   tracker.example.com                    │  3 lines, newest first, no counts
│   ads.foo.net                            │
│   telemetry.bar.dev                      │
└──────────────────────────────────────────┘
```

While a timer is running, the chip row becomes:

```
│   resumes in 4:32              [ Resume ] │
```

The live countdown is local clock math from `timer` + `fetched_at`. Do not wait for the next poll to tick the seconds.

Empty / unconfigured panel is a setup form, not a blank dashboard:

- URL (`http://pi.hole` or `https://192.168.1.2`)
- Password file path (default below)
- Allow insecure TLS
- **Test connection**
- One paragraph: generate a Pi-hole **app password** (Settings → API / app password), put it in the file, `chmod 600`. Web login + 2FA will not work.

Persist those three fields with `omarchy bar set`, same pattern Quadrant uses. Do not invent a second config file for URL.

Open-dashboard control uses `dashboardUrl` if set, else `url`.

## 6. States

Canonical `state` from the helper. QML does not invent a second enum.

| `state` | Meaning | Bar | Panel |
|---|---|---|---|
| `unconfigured` | empty `url` | muted glyph | setup form |
| `enabled` | `blocking: "enabled"` | metric | hero + chips |
| `paused` | `blocking: "disabled"` and `timer != null` | countdown | countdown + Resume |
| `disabled` | `blocking: "disabled"` and no timer | `off` | Enable chip only |
| `offline` | connect / TLS / timeout | `—` | last-good snapshot if any, plus error + Retry |
| `auth` | 401 after retry, missing file, TOTP required | `auth` | setup-ish error: “use an app password” |
| `failed` | 5xx, malformed JSON, unexpected blocking | `—` | error string |

Keep the last successful snapshot on screen when a refresh fails. Label it stale. Weather does this; copy it.

`blocking: "failed"` / `"unknown"` from Pi-hole map to `failed`.

Unreachable is a first-class state. Pi-hole is on another box. Sleep, VPN, DNS chicken-and-egg, self-signed TLS, and wrong port (8080 shows up constantly) are expected. One quiet glyph, tooltip with the error, panel with a retry and the URL you are hitting. No toast every 20 seconds.

The API is source of truth. If blocking was changed from the web UI, the next poll reflects it. Do not keep a local “I paused it” flag that can disagree.

## 7. Settings

Widget schema on the `barWidget` block. Defaults:

```json
{
  "url": "",
  "dashboardUrl": "",
  "passwordFile": "~/.config/omarchy/omapihole.password",
  "allowInsecure": false,
  "refreshSeconds": 20,
  "barMetric": "percent"
}
```

| Key | Type | Notes |
|---|---|---|
| `url` | string | API origin, no trailing path. Empty → `unconfigured`. |
| `dashboardUrl` | string | Optional. Right-click / ↗ target. Empty → `url`. Exists because the API host is often a Docker/LAN IP and the thing you want to open is a Tailscale or reverse-proxy URL. |
| `passwordFile` | path | Mode 600. File may be empty or missing if the Pi-hole needs no auth. |
| `allowInsecure` | bool | Self-signed LAN HTTPS. Default false; setup copy explains when to flip it. |
| `refreshSeconds` | integer | 10–120, default 20. Bar poll only. |
| `barMetric` | enum | `percent` (default), `rate` (`frequency` as q/min), `queries` (compact total). Overridden by pause/off. |

The password itself never appears in `shell.json`, argv that QML can read, or the helper’s stdout. The helper reads the file.

Use a Pi-hole **app password**, not the web login. 2FA makes the web password unusable for this, and app passwords skip TOTP.

## 8. Helper contract

QML does not speak SID. A script at `scripts/omapihole` is the only process that talks to Pi-hole.

```
scripts/omapihole status [--bar]
scripts/omapihole pause <seconds>
scripts/omapihole resume
scripts/omapihole ping
```

Flags come from env, set by QML, not from a second config:

```
OMAPIHOLE_URL
OMAPIHOLE_PASSWORD_FILE
OMAPIHOLE_ALLOW_INSECURE=0|1
```

**`status`** prints one JSON object to stdout, exit 0 even on logical errors (`ok: false`). Non-zero only for usage errors (bad argv).

```json
{
  "ok": true,
  "state": "enabled",
  "error": null,
  "blocking": true,
  "timer": null,
  "queries": {
    "total": 48213,
    "blocked": 16402,
    "percent_blocked": 34.02,
    "unique_domains": 2104,
    "frequency": 1.1
  },
  "gravity": {
    "domains_being_blocked": 187432,
    "last_update": 1725194639
  },
  "history": null,
  "recent_blocked": [],
  "fetched_at": 1770000000
}
```

- `--bar`: `GET /api/stats/summary` + `GET /api/dns/blocking` only. `history` and `recent_blocked` are empty. This is the 20s timer.
- Full `status` (panel open): those two, plus `GET /api/history` and `GET /api/stats/recent_blocked?count=3`.
- `pause N`: `POST /api/dns/blocking` with `{"blocking": false, "timer": N}`, then print a full status.
- `resume`: `POST /api/dns/blocking` with `{"blocking": true, "timer": null}`, then print a full status.
- `ping`: auth + summary only; used by Test connection. Same JSON.

Auth, inside the helper, not in QML:

1. `GET /api/auth`. If `session.valid` already, use it (passwordless / local-trust Pi-holes exist).
2. Else `POST /api/auth` with `{"password": "<file contents trimmed>"}`.
3. If the response says TOTP is required, return `state: "auth"` with a fixed error: app passwords only.
4. Send SID as header `X-FTL-SID` on later calls. User-Agent: `omapihole/0.1`.
5. Cache SID at `~/.local/state/omapihole/session` mode 600. On 401, drop it, re-auth once, retry once. Then fail `auth`.
6. Any authenticated call refreshes the ~30-minute session. A 20s bar poll is enough to keep it alive.

TLS: if `allowInsecure`, curl `-k`. Otherwise verify.

Do not `DELETE /api/auth` on every poll. The session is the point.

## 9. Pi-hole API used (v6 only)

v6 shipped February 2025 with an embedded REST API in `pihole-FTL`. Dual-stack v5 support is how Glance lost months. Skip v5.

| Method | Path | When |
|---|---|---|
| GET | `/api/auth` | session check |
| POST | `/api/auth` | login with app password |
| GET | `/api/stats/summary` | bar + hero |
| GET | `/api/dns/blocking` | on / off / timer |
| POST | `/api/dns/blocking` | pause / resume |
| GET | `/api/history` | sparkline, panel-open |
| GET | `/api/stats/recent_blocked?count=3` | ticker, panel-open |

Map from summary:

- Hero `%` ← `queries.percent_blocked`
- Queries / blocked / unique domains / gravity ← the obvious fields
- `rate` bar metric ← `queries.frequency * 60`, shown as `12/m`

History is ~10-minute buckets, ~145 points. Render the last 24h as ~48 bars (pair adjacent points). Two series: total (muted) and blocked (accent). If length is weird, still draw what arrived; do not error the whole panel.

`recent_blocked.blocked` is a string array. Show up to 3. If empty, hide the section.

Pause timers: **30, 300, 900** seconds. No custom duration in V1.

`GET /api/dns/blocking` returns `blocking` as `"enabled"` / `"disabled"` / `"failed"` / `"unknown"`, and `timer` as remaining seconds or `null`. `POST` takes `{"blocking": false, "timer": 60}` to disable for one minute; `timer: null` makes the mode permanent.

## 10. Visual rules

- Theme colors only. No Pi-hole teal/cyan as a brand overlay.
- Hero is the only large number. The four supporting stats are secondary type, not four equal tiles.
- Sparkline is a composition with the hero, not a chart card with a legend.
- Urgent tint on the header status dot — and the bar — when `paused` or `disabled`. Do not recolor the entire panel background; it will fight light themes.
- Compact numbers: `48213` → `48.2k`, `187432` → `187k`.
- Last-blocked is a list of domains, truncated with ellipsis, no count column, no “top.”
- First-party widgets are the type reference: weather’s pill + panel, Quadrant’s rings only as a quality bar, not as a layout to copy. This panel is closer to Omastonk (one hero, one chart, one action row).

Glance already proved the 3-element layout (percent, 24h bars, short blocked list). Copy the density, not the HTML.

## 13. Acceptance (V1 is done when)

1. Empty `url` → muted glyph, setup form, Test connection.
2. App password in a 600 file → bar shows block % within one refresh.
3. Passwordless Pi-hole (valid session, null SID) works with an empty/missing password file.
4. TOTP-only web password → `auth` state, copy tells you to make an app password. No TOTP prompt.
5. Left click opens the panel; hero, sparkline, four stats, three last-blocked, pause chips.
6. `1` / chip 30s → bar switches to a live countdown; Pi-hole web UI agrees blocking is off; at 0 it returns to %.
7. Resume → bar back to %.
8. Unplug the Pi / bad TLS → bar `—`, panel keeps last-good numbers and an error. No notification spam.
9. Right click opens `dashboardUrl` or `url`.
10. `omarchy plugin validate .` passes. Theme switch (light/dark) does not leave hardcoded colors.

## 14. Build order

Each slice should be installable and look like itself, not a pile of TODOs.

1. **Scaffold** — manifest, empty bar glyph, panel that says unconfigured. Validate + enable.
2. **Helper auth + `ping` / `status --bar`** — prove against a live v6 box before drawing cards. This is the actual risk.
3. **Bar states** — % / off / countdown / — / auth, colors, tooltip.
4. **Panel hero + supporting stats + sparkline** from full `status`.
5. **Pause / resume** — chips, keys 1/2/3/e, live countdown.
6. **Last-blocked + open dashboard + setup form persistence.**
7. **Fixtures + tests + README + preview.**

Do not start at the sparkline. If slice 2 is not boringly solid, the rest is a pretty error.

Auth, sessions, and secrets are the project. The UI is a weekend. Secrets in `shell.json` are a footgun; the password file is not optional.

## 16. Key decisions

| Decision | Choice | Why |
|---|---|---|
| Product spine | Bar state + timed pause, not a stats dashboard | The daily loop is “site broken → pause 5m → it comes back.” Charts are garnish. |
| Name | OmaPihole / `bvisagie.omapihole` | oma* family, GitHub BVisagie, matches `bvisagie.you-got-mail` |
| API | Pi-hole v6 only | v5 dual-stack is a swamp; v6 is the current REST API |
| Auth | App password in a 600 file | `shell.json` is the wrong place for a secret; TOTP web logins cannot be polled |
| Right-click | Open dashboard | Pause is already on chips/keys; misclick-disable is worse |
| Default `barMetric` | `percent` | The number people already know from the Pi-hole homepage |
| Kinds | `bar-widget` only | A `service` for “left off” notifications is V1.1 |
| Fetch | Helper script, not QML | SID, 401 retry, and password I/O do not belong in the shell process UI |
| Scope | One Pi-hole, no AdGuard | First things people will ask for; say no until the one-box path is a daily driver |
| Visual | Theme tokens, one hero, no four equal tiles | Competing with the web UI on completeness loses; competing on glance + action can win |

## 17. Omarchy plugin contract (implementation notes)

- Third-party plugin: git repo with `manifest.json` at the root. `omarchy plugin add https://github.com/BVisagie/omarchy-omapihole.git --enable`
- Plugins run unsandboxed inside `omarchy-shell`. Disclose that in the README.
- `schemaVersion: 1`, `id` not in the reserved `omarchy.*` namespace, entry points as safe relative paths that exist.
- Bar widget extra block: `displayName`, `category`, `defaultSection`, `allowMultiple`, `defaults`, `schema`.
- Saving files under `~/.config/omarchy/plugins/` hot-reloads. `omarchy plugin validate .` before publish.
- Settings live on the widget’s bar-layout entry in `~/.config/omarchy/shell.json`. Write them from the panel with `omarchy bar set bvisagie.omapihole <key> <value>` via `bar.run(...)`.
- Panel wiring: `BarWidget.qml` loads `Panel.qml` in a hidden Loader, injects `bar`, `settings`, `anchorItem`, `hostWidget`. Same shape as weather / Quadrant.

## 18. Risks that will actually bite

1. **Secrets.** Plugin settings in `shell.json` are a bad place for a Pi-hole password. Password file mode 600 is mandatory.
2. **Unreachable.** Offline must be quiet and first-class, not a toast storm.
3. **Session expiry.** Default ~30 minutes; any authenticated poll extends it. 20s bar poll is enough. Still handle 401 with one re-auth.
4. **Self-signed TLS and odd ports.** `allowInsecure` and a URL with an explicit port. Dashboard URL often differs from API URL.
5. **Passwordless vs 2FA.** Empty password / local-trust sessions return `valid: true` with a null SID. TOTP web passwords must fail closed with copy, not a TOTP prompt.

---

## 19. When not to build this

If the goal is “a homelab status board on the desktop,” a Glance/Homepage page in a dedicated workspace is better.

If the goal is “the shell should know whether the hole is open,” this is a sharp, small Omarchy plugin. Nobody has published one in the community directory. The pattern is proven. The API is good enough. The design constraint — do not replace the dashboard — is correct as long as **pause/resume** sits at the center instead of the charts.
